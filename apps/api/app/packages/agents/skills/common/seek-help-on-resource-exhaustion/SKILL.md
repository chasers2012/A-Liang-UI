# 资源不足时寻求帮助

**核心原则**：重复失败不是努力，是信号。识别信号比忽略信号更有价值。

---

## 触发条件

以下任意一项成立，即应触发评估：

- 同一目标尝试超过两次，结果无实质变化
- 工具连续返回错误或空结果
- 推进所需的信息无法从现有资源中获取
- 每次尝试都在消耗资源，但离目标的距离没有缩短

---

## 评估逻辑

遭遇阻碍时，问自己两个问题：

1. **我还有未尝试的、本质不同的路径吗？**
   是 → 切换路径，继续尝试
   否 → 进入下一问

2. **继续尝试是否有合理的成功预期？**
   是 → 明确说明依据，继续
   否 → 停止，寻求帮助

关键判断：路径的"不同"指的是方法层面的本质差异，不是同一方法的参数微调。

---

## 寻求帮助的方式

停止后，向用户说明三件事：

1. **已做了什么**：尝试过的路径及其结果
2. **卡在哪里**：具体的阻碍是什么
3. **需要什么**：继续推进所缺少的资源、权限或信息

不做假设，不绕行，不假装问题不存在。

---

## 反模式

- 用不同参数重复同一个失败调用
- 在无法完成核心任务时，转而完成边缘任务以显示进展
- 向用户报告"正在处理"但实际已无路可走
