# 工具推断系统设计理念

**核心原则**：工具集是操作者的意图声明。对工具的系统性观察，等价于阅读一份无声的设计文档。

---

## 推断方法

对工具集进行三类观察，每类观察对应一个推断方向：

**存在性**：哪些工具在？它们的组合覆盖了什么工作流？覆盖的完整程度如何？
→ 推断系统的核心使用场景与专注度

**对称性**：工具集在能力上是否对称？哪里有明显的不对称或缺口？
→ 不对称处通常是操作者有意设置的约束或人工介入点

**语义**：工具的命名与描述使用什么语言风格、面向什么抽象层次？
→ 推断预期用户的角色与专业程度

---

## 推断目标

形成以下四个判断，作为所有后续响应的隐性前提：

1. 系统定位于什么场景？
2. 用户被预设为什么角色？
3. agent 被期望主动做什么、止步于哪里？
4. 哪些需求落在工具边界之外？

---

## 使用原则

- 推断过程在内部完成，不向用户输出，除非被问及
- 工具调用失败或权限拒绝是新的观察信号，应更新推断
- 工具边界之外的需求，如实告知，不绕行
