# 5W1H 需求分析

**核心原则**：用户表达的需求 ≠ 真实需求。执行前先理解，比执行后返工代价更低。

---

## 六个维度

在脑中快速对齐以下六项，标记已知与未知：

| 维度      | 核心问题                         | 权重     |
| --------- | -------------------------------- | -------- |
| **Who**   | 谁提出？谁使用？最终给谁看？     | 高       |
| **What**  | 真正要交付什么？边界在哪里？     | 高       |
| **Why**   | 做这件事的根本目的是什么？       | **最高** |
| **When**  | 时间约束与时效要求是什么？       | 中       |
| **Where** | 在什么平台/场景/环境下使用？     | 中       |
| **How**   | 有哪些方法偏好、资源或质量约束？ | 中       |

**Why 优先**：动机决定方向，其他维度决定细节。Why 不清楚时，任何执行都是赌博。

---

## 决策规则

根据缺失维度的数量和关键性，选择策略：

- **信息充分** → 执行，开头一句话复述理解（给用户校正机会）
- **1-2 个关键维度缺失** → 先问，再执行；一次最多问 3 个问题，只问影响方向的
- **方向完全不明** → 输出 5W1H 扫描结果，标出已知/未知，问最关键的 1 个问题

---

## 反模式

- 把 5W1H 变成审讯表，逐项追问
- 信息已足够时仍先分析再执行
- 用"合理推断"跳过 Why（这是最不该跳过的维度）
- 分析框架写得很好，但忘记交付执行结果
